**Status:** frozen for the Aug 19 demo. Any change must be announced in the team chat and the version bumped.
**Owner:** backend (Shikun Zhang)
**Consumers:** Pi firmware (hardware lead), staff dashboard (frontend), Azure infra (deployment lead)

Base URL (dev): `http://<backend-laptop-ip>:7071/api`

Auth:
- Device endpoints: header `X-Device-Key: <shared secret>` (per-device key, issued by backend).
- Dashboard endpoints: signed-in user session; every mutation is attributed to an account.

## 1. `POST /voice/turn` — the only endpoint the Pi calls

One completed utterance = one call. The Pi holds **no** dialogue state; the response tells it what to do next.

### Request

```json
{
  "session_id": "s-a3f9c1",
  "turn": 1,
  "device_id": "pi-3f-01",
  "location": "3F-Washroom",
  "transcript": "the printer on floor two is jammed",
  "stt_confidence": 0.88,
  "timestamp": "2026-08-06T13:40:12Z"
}
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `session_id` | string | yes | Generated by the Pi on the **first** turn (`s-` + 6 hex chars). Reused for follow-up turns. Server expires it after 60s idle. |
| `turn` | int | yes | Starts at 1, increments per utterance in the same session. |
| `device_id` | string | yes | Stable per panel. |
| `location` | string | yes | Panel's physical location, from device config. May be overridden by what the user says. |
| `transcript` | string | yes | Text only. Never send audio. Empty string is rejected with 400. |
| `stt_confidence` | float 0–1 | yes | Vosk score. Server may ask the user to repeat if below threshold. |
| `timestamp` | ISO-8601 UTC | yes | **Time of the utterance**, not time of send. This is what makes offline retry non-duplicating. |

### Response — `200 OK`

Always this shape, for all four intents.

```json
{
  "session_id": "s-a3f9c1",
  "turn": 1,
  "intent": "new_request",
  "state": "complete",
  "listen_again": false,
  "request": {
    "request_id": "REQ-3FW-0817",
    "category": "cleaning",
    "location": "3F-Washroom",
    "priority": "medium",
    "assigned_team": "custodial",
    "confidence": 0.91,
    "safety_flag": false,
    "missing_fields": []
  },
  "device_actions": [
    { "actuator": "led_green", "action": "pulse", "duration_ms": 3000 },
    { "actuator": "lcd", "action": "show", "text": "REQ-3FW-0817" }
  ],
  "speech_reply": "Got it. A cleaning request for the third floor washroom has been sent to the custodial team.",
  "audio_format": "mp3",
  "audio_b64": "SUQzBAAAAAA..."
}
```

**Fields the firmware must act on:**

| Field | Values | Firmware behaviour |
|---|---|---|
| `state` | `complete` \| `awaiting_user` \| `escalated_to_human` \| `rejected` | Informational; drive behaviour off `listen_again` and `device_actions`. |
| `listen_again` | bool | `true` → after playing the audio, reopen the mic **without** requiring a button press, same `session_id`, `turn + 1`. |
| `device_actions` | array | Execute in order. Already validated server-side against the whitelist — no unknown actuator can appear here. |
| `speech_reply` | string | Text of the reply. Speak this with local Piper **if `audio_b64` is empty or missing**. |
| `audio_b64` | string \| `""` | Base64 MP3, 16 kHz mono. Empty = TTS failed/timed out, use fallback. |
| `request` | object \| `null` | `null` for `status_query` answers and `out_of_scope`. |

`intent` ∈ `new_request` | `status_query` | `clarification_answer` | `out_of_scope`

### Actuator whitelist (frozen — hardware lead implements exactly these)

| `actuator` | `action` | Extra fields | Meaning |
|---|---|---|---|
| `led_blue` | `on` \| `off` \| `pulse` | `duration_ms` | Listening |
| `led_amber` | `on` \| `off` \| `pulse` | `duration_ms` | Thinking / awaiting user |
| `led_green` | `on` \| `off` \| `pulse` | `duration_ms` | Complete |
| `led_red` | `on` \| `off` \| `blink_fast` | `duration_ms` | Safety / error |
| `buzzer` | `beep_short` \| `beep_double` \| `pattern_urgent` | `duration_ms` | |
| `lcd` | `show` \| `clear` | `text` (≤ 32 chars, 2×16) | |
| `speaker` | `play_reply` | — | Play `audio_b64`, else speak `speech_reply` |

Anything not in this table is dropped by the API before it reaches the device. The firmware should still ignore unknown actuators defensively.

### Errors

| Code | Body `error` | Firmware behaviour |
|---|---|---|
| 400 | `invalid_payload` | Red LED, short buzzer, do not retry |
| 401 | `bad_device_key` | Red LED, log, do not retry |
| 429 | `rate_limited` | Amber, retry once after 2s |
| 500 / 503 | `internal` / `upstream_unavailable` | Queue transcript locally with original timestamp, retry on reconnect |
| timeout (>8s) | — | Same as 503 |

Error body:
```json
{ "error": "invalid_payload", "message": "transcript must be non-empty", "session_id": "s-a3f9c1" }
```

**Idempotency:** retries must reuse the same `session_id` + `turn` + `timestamp`. The server deduplicates on that triple, so a queued-and-retried transcript never creates a second ticket.

## 2. Dashboard endpoints

### `GET /requests?status=&location=&since=`
```json
{
  "items": [
    {
      "request_id": "REQ-3FW-0817",
      "created_at": "2026-08-06T13:40:12Z",
      "location": "3F-Washroom",
      "device_id": "pi-3f-01",
      "transcript": "the printer on floor two is jammed",
      "category": "cleaning",
      "priority": "medium",
      "assigned_team": "custodial",
      "confidence": 0.91,
      "safety_flag": false,
      "flag_source": null,
      "status": "open",
      "acknowledged_at": null,
      "acknowledged_by": null,
      "completed_at": null,
      "resolution_time_s": null
    }
  ],
  "continuation_token": null
}
```

`status` ∈ `open` | `acknowledged` | `escalated` | `completed`
`flag_source` ∈ `null` | `keyword` | `agent`

### `GET /requests/{id}` → single item, same shape.
### `POST /requests/{id}/ack` → `{ "status": "acknowledged", "acknowledged_by": "...", "acknowledged_at": "..." }`
### `POST /requests/{id}/complete` → `{ "status": "completed", "resolution_time_s": 412 }`
### `GET /reports/summary?from=&to=` → counts by category / team / priority, mean resolution time.
### `POST /requests/simulate` → creates a request from typed text, bypassing the Pi. **Demo backup path — build this early.**

### `GET /health`
```json
{ "status": "ok", "agent": "ok", "speech": "ok", "storage": "ok", "version": "1.0.3" }
```
Deployment lead points the App Insights availability test at this.

## 3. Environment variables (deployment lead provisions; backend consumes)

Never in code, never in git. Set in App Settings / Key Vault.

| Name | Purpose |
|---|---|
| `AZURE_STORAGE_CONNECTION_STRING` | Table Storage |
| `TABLE_REQUESTS` | Requests table name (`requests`) |
| `TABLE_SESSIONS` | Conversation session table (`sessions`) |
| `AI_FOUNDRY_ENDPOINT` | Agent endpoint |
| `AI_FOUNDRY_AGENT_ID` | Routing Agent id |
| `AI_FOUNDRY_KEY` | Agent auth (or managed identity — preferred) |
| `SPEECH_KEY` / `SPEECH_REGION` | Azure AI Speech |
| `SPEECH_VOICE` | e.g. `en-CA-ClaraNeural` |
| `SPEECH_TIMEOUT_MS` | Default `2500` |
| `DEVICE_KEYS` | Comma-separated `device_id:key` pairs |
| `SESSION_TTL_SECONDS` | Default `60` |
| `STT_CONFIDENCE_THRESHOLD` | Default `0.55` |
| `ESCALATION_MINUTES` | Unacknowledged high-priority timeout |
| `APPLICATIONINSIGHTS_CONNECTION_STRING` | Telemetry |

## 4. Storage schema (Azure Table Storage)

**`requests`** — PartitionKey = `location`, RowKey = `request_id`
All fields from the dashboard item shape above, flat.

**`sessions`** — PartitionKey = `device_id`, RowKey = `session_id`
`turns` (JSON array of `{turn, transcript, agent_state}`), `expires_at`. Deleted on completion or TTL.
